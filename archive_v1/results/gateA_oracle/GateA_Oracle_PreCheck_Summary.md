**核心发现**：
1. **误拆分规模远大于误合并（FS 是 FM 的 3–10 倍）**：单纯只做“簇内切分（`SPLIT_SEAM`）+ 单帖桥接”会漏掉最大杠杆源；引入**对称介观簇对查询（`MERGE_PAIR`）**后，单次查询即可对齐几十至数百条未查询帖子。
2. **簇内不纯事件呈“偏态少数口袋（10%–25%）”形态**：平衡 Fiedler 二分容易把主事件对半切，导致 `SmHit` 偏低，也使得大簇合并时偶发夹带小块杂质（`NetFM = -1,363`）；这是下一轮升级 `SPLIT_SEAM`（改为簇内子聚少数口袋检测）的明确抓手。
3. **严格 No-Op 保护与分布式桥接至关重要**：初版发现在 LLM 确认“归属不变”时强行剪边、或给 6 个 Medoid 注入过大边权都会导致 2D SE 误撕裂；修复为**严格 No-Op 保护 + 分布式中权语义桥接 + 约束热启动 2D SE** 后，Branch 2 全面反超 Branch 1。

## 三、阶段结论与下一步真实 LLM Gate A 入口

1. **Oracle 上界预检明确通过**：仅用 **~1%–3% 的预算**，介观结构路由相比 `Rep-Div` 与 `Cequel-Edge` 实现 **10× 以上**的未查询帖传播杠杆；且在**完全相同判决**下，Branch 2（约束图拓扑修复 + 2D SE 重聚类）在全部 3 个预算档位上均稳定反超 Branch 1（直接编辑），额外带来 **+0.70pp ~ +1.09pp 事件宏 $B^3$** 与 **+0.50pp ~ +0.76pp 未查询帖宏 $B^3$** 增益。
2. **下一步待执行（真实 LLM Gate A 最终裁决）**：
   * Oracle 检验的是机制上界而非真实模型噪声下的净收益；
   * 需使用真实 LLM（如 Qwen2.5-7B / Qwen-Plus / DeepSeek API，整套 4 块 3 策略 40k Token 预算仅需约 120k 总 Token、成本不足 1 元）运行 `trackA_sug_sed/run_gateA_real_llm.py`，检验在真实 LLM 误判噪声下：
     1. `SUG-Router` 是否仍显著胜过同真实 Token 预算的 `Rep-Div` 与 `Cequel-Edge`；
     2. Branch 2（修边重聚类）是否仍稳定胜过 Branch 1（同判决直接编辑）。
